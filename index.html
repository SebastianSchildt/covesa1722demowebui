Native CAN

CAN data is directly received by the Vehicle Computer.

CAN messages are then converted into COVESA Vehicle Signal Specification (VSS) signals using the KUKSA framework. This enables platform-independent SDV applications.

For example, the UI you are currently looking at, is written using web-technologies. It displays information from the electromechanical layer, accessed as VSS formatted SDV data from the KUKSA databroker component.

CAN over IEEE-1722

CAN data is received by the Zone Controller.

The Open1722 software puts received CAN frames into IEEE-1722 ACF-CAN frames and sends them via Ethernet to the vehicle computer.

Open1722 presents the IEEE-1722 ACF-CAN stream as a standard Linux CAN device.

CAN messages are then converted into COVESA Vehicle Signal Specification (VSS) signals using the KUKSA framework. This enables platform-independent SDV applications. This is exactly the same stack that runs on native CAN.
