IEEE-1722 ACF-CAN

Native CAN

CAN data is received by the Vehicle Computer. It is then converted into COVESA Vehicle Signal Specification (VSS) format by a KUKSA provider, enabling platform-independent SDV applications (such as this web client you are seeing that uses Web technology to display the data received from the electromechanical embedded layer).

CAN over IEEE-1722

CAN data is received by the Zone Controller. It is packaged into IEEE-1722 ACF-VSS frames and forwarded via Ethernet. A Open1722-based device driver converts the IEEE-1722 stream into a standard Linux CAN device. From the virtual CAN device It is then converted into COVESA Vehicle Signal Specification (VSS) format by a KUKSA provider, enabling platform-independent SDV applications (such as this web client you are seeing that uses Web technology to display the data received from the electromechanical embedded layer).
